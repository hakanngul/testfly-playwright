# ADR-001: TestFly foundation (monorepo, config, data contract, healing, honesty)

- **Status:** Accepted
- **Implemented in:** `5ffcfc0` (pnpm monorepo and shared contracts), `351228a` (foundation: config, fixtures, clients, reporter, healing, ai)
- **This document:** reconstructed after the fact from the source code. The original ADR text was not committed. Decisions D2, D4, D5 and D7 are cited by number in source comments and are stated here as the code shows them. The source does not cite D1, D3 or D6 by number. Their entries below are inferred from the code structure and are marked as such. The original author should confirm their numbering.

---

## Context

TestFly started as a single npm package (`src/`, `bin/`, `package-lock.json`). In that layout BDD, locators, clients, mobile helpers, AI ideas and reporting were all in one module. Configuration came from a separate `testfly.config.ts` loaded through a global accessor (`getTestFlyConfig()`). Some helpers silently returned success, or fell back to fake data, when a backend was missing.

The framework needed:

- independently versioned and publishable parts (core, reporter, AI, scaffolder) with clear dependency directions,
- configuration that works with Playwright's own project/worker model and has no process-global state,
- a stable way for test workers to send telemetry (heals, steps, API calls, AI usage) to a reporter that runs in another process,
- deterministic, explainable locator self-healing that can be extended (for example by AI) without coupling the core to an LLM,
- failures that tell the user exactly what is wrong instead of passing silently.

## Decisions

### D1 (inferred): pnpm monorepo with separately published packages

*Evidence:* commit `5ffcfc0` "convert to pnpm monorepo and add shared contracts (ADR-001)"; `pnpm-workspace.yaml` (`packages/*`); `.changeset/`; per-package `package.json` with `exports`, `publishConfig.provenance`, `engines.node >= 22`.

| Package | Role | Depends on |
| --- | --- | --- |
| `@testfly/reporter` | Data contract + Playwright reporter | none of the other packages (`zod`, `yaml` only) |
| `@testfly/playwright` | Core framework, fixtures, CLI | `@testfly/reporter` (for the schema) |
| `@testfly/ai` | Optional AI layer | `@testfly/reporter`; peer `@testfly/playwright` |
| `create-testfly` | Scaffolder | none |
| `@testfly/mobile` | Experimental, `private: true`, not published | none |

*Rationale (as evidenced):* the reporter can run in any Playwright project without the core ("It does not depend on `@testfly/playwright`", `packages/reporter/README.md`). AI is opt-in and does not add LLM code to the core. Database and mail drivers (`pg`, `mysql2`, `ioredis`, `imapflow`) are optional peer dependencies, loaded lazily through `importOptional()` (`packages/playwright/src/core/errors.ts`).

### D2: options live in the Playwright config and reach tests as a fixture, with no global singleton

*Cited in:* `packages/playwright/src/core/config/schema.ts` ("TestFly options schema (ADR-001 D2)"), `packages/ai/src/assertions/matchers.ts` ("there is no global configuration singleton (ADR-001 D2)").

- Users write `defineConfig({ testfly: {...} })` from `@testfly/playwright/config`. The `testfly` key is validated with zod (`TestFlyOptionsSchema`).
- The resolved options reach tests through the worker-scoped option fixture `testfly` (`coreTest`, `fixtures/core.ts`). Projects override them through `use: { testfly: {...} }`, which is deep-merged over the root options.
- `defineConfig` also resolves `${VAR}` from `process.env`/`.env`, applies `profiles[TESTFLY_ENV ?? env]`, sets `use.baseURL` from `testfly.baseUrl`, wires `playwright-bdd` when `testfly.bdd` is set, and appends `@testfly/reporter` unless `reporter.enabled` is `false`.
- Code that cannot receive a fixture directly looks up state per test instead of reading a global. For example, `@testfly/ai` keeps a `WeakMap<TestInfo, AiRuntime>` that its `_aiRuntime` auto fixture fills.

*Rationale (as evidenced):* this matches Playwright's project/worker model (per-project overrides, worker isolation). The separate `testfly.config.ts` and its global accessor were removed.

### D3 (inferred): composable fixture sets merged with `mergeTests`

*Evidence:* `packages/playwright/src/fixtures/index.ts`. Each capability is its own `test.extend` set built on `coreTest`: `apiTest`, `dataTest`, `locatorTest`, `qualityTest`, `mockTest`, `sessionTest`, `quarantineTest`. The default `test` merges all of them. All sets are exported publicly. BDD reuses the same fixtures: `@testfly/playwright/bdd` merges playwright-bdd's base `test` with TestFly's `test` and binds `Given/When/Then` to it with `createBdd`.

- Expensive connections (`db`, `redis`, `mail`) are worker-scoped and lazy: they are created only when a test requests them.
- Cross-cutting behaviour (quarantine skipping) is an auto fixture.

*Rationale (as evidenced):* users can build a leaner `test` with `mergeTests`. Step definitions get the same fixtures as spec tests. Unused integrations cost nothing.

### D4: versioned data contract between workers and the reporter

*Cited in:* `packages/reporter/src/schema.ts` ("TestFly data contract (ADR-001 D4) — version 1").

- Workers communicate with `@testfly/reporter` **only** through Playwright attachments with vendor content types: `application/vnd.testfly.{heal,step,api,ai,meta}+json` (`CONTENT_TYPES`).
- The reporter aggregates them into `RunRecord` files `<outputDir>/history/run-<timestamp>-<shard>.v1.json` (`SCHEMA_VERSION = 1`).
- Every analytic feature reads only this schema: Flakiness Radar, triage, quality gate, LPT sharder, AI failure analysis and the dashboard.
- A breaking change requires a new major schema version (v2) and a migration.
- The schema is a separate entry point (`@testfly/reporter/schema`) so producers (`@testfly/playwright`, `@testfly/ai`) can import it without importing the reporter.

*Rationale (as evidenced):* attachments are the only channel Playwright gives from worker processes to reporters. A versioned zod schema lets history files outlive releases.

### D5: layered, pluggable locator healing

*Cited in:* `packages/playwright/src/locators/healing/types.ts` ("Healing contracts (ADR-001 D5)").

Resolution order for `locate(key)`:

1. the primary definition from YAML,
2. explicit `fallbacks:` in YAML,
3. registered `HealingStrategy` implementations by ascending `priority`: rules (10), fuzzy (20), AI (100).

- `testfly.healing.mode` selects `off`, `rules` (YAML fallbacks + rules + fuzzy, zero tokens) or `ai` (rules first, then `@testfly/ai`). The `ai` mode imports `@testfly/ai` lazily and throws `TF_OPTIONAL_DEPENDENCY_MISSING` if it is not installed.
- Third parties can add strategies through `registerHealingStrategy`.
- Every successful heal produces a `HealEvent` that is attached as `application/vnd.testfly.heal+json` (D4). The reporter aggregates heal events, and the quality gate can fail the run on any heal (`qualityGate.failOnHeal`).

*Rationale (as evidenced):* cheap deterministic strategies run before expensive ones. The core has no LLM dependency. Heals are always visible.

### D6 (inferred): AI is optional, cached and replayable

*Evidence:* `packages/ai` is a separate package. `AiOptionsSchema` (`schema.ts`) defines `mode: 'live' | 'replay' | 'off'`. In `replay` a cache miss throws `TF_AI_CACHE_MISS` (`packages/ai/src/runtime.ts`). Caches are JSON files under `cacheDir` (default `.testfly`). Providers are called over plain `fetch` (no vendor SDKs). Content is redacted before it leaves the machine (`context/redact.ts`). AI failure analysis is a separate, opt-in reporter (`@testfly/ai/reporter`) that never fails the run.

*Rationale (as evidenced):* CI runs can be deterministic and free (`replay`). Only cache misses cost tokens in development.

### D7: honesty principle and a single error model

*Cited in:* `packages/playwright/src/core/errors.ts` ("TestFly error model (ADR-001 D7: honesty principle)").

- Every failure raised by TestFly is a `TestFlyError` with a stable `TestFlyErrorCode` (`TF_CONFIG_INVALID`, `TF_DB_NOT_CONFIGURED`, `TF_LOCATOR_NOT_FOUND`, `TF_AI_CACHE_MISS`, ...), a readable message, an optional `hint` and a docs link.
- TestFly never falls back silently to fake or mock data. In-memory backends (`db.client: 'mock'`, `mail.provider: 'mock'`) exist only as explicit choices. Using `db`/`redis`/`mail` without config throws `TF_DB_NOT_CONFIGURED` / `TF_MAIL_NOT_CONFIGURED`.
- A metric that cannot be measured is reported as `null`, not estimated, and asserting it throws `TF_QUALITY_UNSUPPORTED` (`quality/performance/PerformanceClient.ts`).
- Missing optional packages throw `TF_OPTIONAL_DEPENDENCY_MISSING` with an install hint (`importOptional`).

*Rationale (as evidenced):* a passing test must mean that the checked behaviour really happened.

## Consequences

**Positive**

- Consumers install only what they use. The reporter works in plain Playwright projects.
- Configuration is type-checked and validated at config load time. Invalid options fail fast with `TF_CONFIG_INVALID`.
- Reporter features (flakiness, triage, gates, sharding, dashboard) share one schema and can be tested in isolation.
- Healing behaviour is explicit, ordered and observable in reports.

**Negative / costs**

- Breaking API changes compared with the pre-monorepo package: `defineTestFlyConfig`, `testfly.config.ts`, root-level `Given/When/Then` exports, `scenarioContext`, `performance.assertThresholds` and the `elements:`-nested locator YAML no longer exist. Older documentation and examples must be migrated.
- More release machinery: per-package builds (`tsup`, ESM + CJS), changesets, `publint`/`attw`.
- The data contract is now a public compatibility surface. Schema changes need versioning and migrations.
- Some D7-style guarantees depend on each package following the rule. Packages outside the foundation (for example the experimental `@testfly/mobile`) must be brought in line separately.

**Follow-ups visible in code**

- `@testfly/ai/reporter` writes `ai-analysis.json`. The `@testfly/reporter` dashboard does not embed it yet (stated in `packages/ai/src/reporter.ts`).
- The locator schema reserves `ios`/`android`/`mobile` keys but ignores them ("mobile is deferred", `locators/schema.ts`).
