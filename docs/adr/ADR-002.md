# ADR-002: Native mobile testing on Mobilewright

- **Status:** Accepted (experimental: `@testfly/mobile` stays `private` and unpublished)
- **Scope:** `packages/mobile`, `packages/playwright` (`testfly.mobile`, YAML `ios`/`android`/`mobile` blocks, `bdd.importTestFrom`)

---

## Context

`@testfly/mobile` used to ship only a driver-agnostic API (`MobileClient`, `MobileScreen`, `MobileLocator`). It had no driver, so it could not drive a device. ADR-001 D7 forbids silent passes, so every call threw `TF_FEATURE_DISABLED`. The locator YAML accepted `ios:`/`android:` keys but ignored them.

[Mobilewright](https://mobilewright.dev) (Apache-2.0) is a Playwright-style API for iOS and Android. It provides `ios.launch()`/`android.launch()`, `device.screen.getByRole/getByText/getByTestId/…`, auto-waiting actions and a retrying `expect`. It drives simulators, emulators and real devices through [mobilecli](https://github.com/mobile-next/mobilecli), without Appium. mobilecli has a different license (FSL). It is installed as a dependency of `mobilewright`, so TestFly neither bundles nor redistributes it.

## Decisions

### D1: Build on the `mobilewright` launcher, not on `@mobilewright/test`

`@mobilewright/test` pins its own `@playwright/test` version (1.63 at the time of writing). A TestFly project already has `@playwright/test`. Two copies of the test runner in one project break fixtures and the CLI. `@testfly/mobile` therefore uses only the runtime package `mobilewright`, which does not import the test runner. TestFly provides the fixtures itself:

| Fixture | What it is |
| --- | --- |
| `device` | A Mobilewright `Device` launched from `testfly.mobile` for each test and closed afterwards. |
| `mobileScreen` | `device.screen`. It is named differently because Playwright already has a built-in `screen` option, the viewport size of web contexts. |
| `mobileLocate(key)` | A YAML locator key resolved to a Mobilewright locator for the configured platform. |
| `mobileDriver` | Option (`test.use`). A custom Mobilewright driver, for example a fake or a device cloud. |

All TestFly fixtures (`ctx`, `api`, `locators`, …) are available too. `@testfly/mobile/bdd` merges these fixtures with `@testfly/playwright/bdd`.

### D2: `mobilewright` is an optional peer dependency

`mobilewright` is ESM-only and loaded with a real `import()` on first use. When it is missing, the error is `TF_OPTIONAL_DEPENDENCY_MISSING` with an install hint. The CommonJS build is produced without code splitting so that `import()` is not rewritten to `require()`. The loaded module is cached on `globalThis` so the `.` and `/bdd` bundles share it.

### D3: One locator catalog for web and native

A YAML entry may hold `ios:`, `android:` and `mobile:` blocks next to its web definition. `mobileLocate` picks the platform block first, then `mobile:`, then the shared definition when it uses only fields that exist on mobile (`role`/`name`, `label`, `text`, `testid`, `placeholder`). It ignores web-only fallbacks (`css`, `xpath`, `alt`, `title`). A block also accepts `type` (native element type). A plain string is a test id. Entries with only native blocks are allowed; the web `locate()` rejects them with `TF_LOCATOR_INVALID`.

### D4: One `expect`

`expect` from `@testfly/mobile` sends Mobilewright locators to Mobilewright's matchers. Everything else (values, web locators, API responses) goes to the TestFly/Playwright `expect`. Mobilewright's default soft-assertion handler throws. The `device` fixture replaces it so that `expect.soft` records the failure on the Playwright test and the test continues.

### D5: Honest failures (ADR-001 D7)

- No `testfly.mobile` → `TF_CONFIG_MISSING`.
- Launch/connect errors → `TF_MOBILE_LAUNCH_FAILED`, with the original error as `cause`.
- A key without a definition for the platform → `TF_LOCATOR_NOT_FOUND`. A circular `within` chain → `TF_LOCATOR_INVALID`.
- A device screenshot is attached (`mobile-screenshot`) when a test fails or times out (`screenshotOnFailure`, default true).

### D6: Verified without devices

The package tests run Mobilewright against an in-memory fake driver (`test/support/fakeDriver.ts`) through `LaunchOptions.driver`. There are vitest unit tests, a Playwright suite (`e2e/`, iOS and Android projects) and a playwright-bdd suite (`e2e-bdd/`). Runs on real simulators and devices (macOS + Xcode, Android SDK) are not part of CI yet.

### D7: A single Playwright version in the workspace

`mobilewright` depends on `playwright@1.63.0`. With pnpm, that copy can end up in the hidden hoist directory. playwright-bdd resolves `playwright` from there, so its runtime no longer matched the test runner (`bddTestData not found`). The workspace pins `playwright` and `playwright-core` to the `@playwright/test` version (`pnpm.overrides`). pnpm consumers should do the same (see `packages/mobile/README.md`).

## Consequences

- Native tests use the same config, YAML catalog, data and reporting as web tests.
- The API follows Mobilewright's names (`device`, `screen` → `mobileScreen`, `getBy*`, `tap`, `fill`). Mobilewright is pre-1.0 (`0.0.x`), so the peer range is narrow (`>=0.0.66 <0.1.0`) and the package stays experimental.
- The old driver-agnostic API (`MobileClient`, `MobileScreen`, `MobileLocator`, `MobileDriver`) is removed. It was private and could not drive a device.
- Open: device allocation for parallel workers (Mobilewright's device pool), Mobilewright's own reporter/observer, publishing the package.
